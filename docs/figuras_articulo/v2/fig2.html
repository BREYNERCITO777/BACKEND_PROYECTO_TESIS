Alert flow

1The agent reads each RTSP stream in its own thread and keeps only the latest frame.
2YOLOv8s analyses the new frames of all cameras in one batch; a detection at or above the threshold (0.65) is sent with one evidence image, at most once per camera every 5 s.
3The backend checks the agent token, the threshold and the cooldown, then stores the incident and the alert.
4MongoDB keeps the incident record and the evidence image.
5The alert is broadcast over WebSocket to every connected dashboard.
6The operator reviews the evidence image and decides; the system never acts on its own.
HTTP(S): HTTP on port 80 inside the municipal network in production (Supplementary Figure S4); HTTPS in the cloud prototype evaluated in this study.
