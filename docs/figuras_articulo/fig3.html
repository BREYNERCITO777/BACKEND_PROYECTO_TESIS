Sentinel AI: Configuration and Infrastructure

Containerized environment for development and the end-to-end demonstration (demo/docker-compose.yml)

Host machine

Windows, Linux or macOS
  • Docker Engine or Docker Desktop
  • Optional NVIDIA GPU (driver + container toolkit)
  • Browser or API client at localhost:8000
DOCKER COMPOSE · demo/docker-compose.yml · internal network

backend

Image built from Dockerfile (python:3.9-slim)
FastAPI on Uvicorn · port 8000 published · model app/models/best.pt (v5)
Environment: MONGO_URL, AGENT_TOKEN, JWT_SECRET
Health check: GET /docs before the agent starts

mongo

Official image mongo:7
Reached only by the backend at mongodb://mongo:27017; no port published
Collections: users, cameras, incidents, alerts, settings

agente

Image built from agente/Dockerfile (python:3.10-bookworm, OpenCV, Ultralytics)
Reads video_demo.mp4 (mounted volume) as if it were an RTSP camera, runs the same best.pt and sends detections to http://backend:8000/api/v1/agent/detections with the agent token · threshold 0.65 · cooldown 5 s

Configuration and key files

Dockerfile · agente/Dockerfile: build the two images from the same repository
requirements.txt (both): pinned versions, Ultralytics 8.3.40, PyTorch 2.8.0, torchvision 0.23.0, NumPy 2.0.2
.env from .env.example (not versioned): AGENT_TOKEN, JWT_SECRET, RTSP_SECRET_KEY, MONGO_URL, CORS_ORIGINS, EVIDENCE_RETENTION_DAYS
app/models/best.pt: one model file copied into both images
.github/workflows/tests.yml: on every commit, MongoDB service + backend + pytest
Images tagged 1.0.0; git tag v1.0.0-revision
